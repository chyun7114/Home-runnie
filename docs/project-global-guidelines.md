# 프로젝트 공통 지침

이 문서는 저장소 전체에 적용되는 기본 개발 지침이다.

## 1. 설계 원칙

- 신규 구현 및 리팩터링 시 SOLID 원칙을 기본 기준으로 적용한다.
- 단일 책임 원칙(SRP)을 우선하며, 변경 이유가 다른 로직은 분리한다.
- 의존성 역전 원칙(DIP)을 적용해 상위 레이어가 하위 구현체에 직접 결합되지 않도록 한다.

## 2. 문서 작성 원칙

- 모든 `*.md` 문서는 한국어로 작성한다.
- 영어 전용 문서 작성은 금지한다.
- 코드, 명령어, 라이브러리/클래스/함수명 등 고유 식별자는 원문 표기를 허용한다.

## 3. 코드 품질 원칙

- ESLint 규칙 준수는 필수다.
- 코드 변경이 포함된 작업은 대상 파일 기준 ESLint 검증을 반드시 통과해야 한다.
- 자동 수정 가능한 항목은 우선 수정하고, 남는 경고/오류는 원인과 처리 계획을 PR에 기록한다.

## 4. TDD 원칙

- 기능 구현 전 테스트를 먼저 작성한다.
- 기본 사이클은 `Red -> Green -> Refactor`를 따른다.
- 테스트는 변경 범위에 맞춰 단위/통합/E2E 레벨 중 필요한 수준까지 추가한다.
- 버그 수정 시에는 재현 테스트를 먼저 추가한 뒤 수정한다.
- PR에는 "추가한 테스트"와 "실행한 검증 명령"을 반드시 기록한다.
